PhanthyMovie · 产品逻辑说明 v0.1

关键帧 · CanvasFlow Studio

一款基于"画布 + 时间线"的 AI 短片创作工具。用户在画布上摆放图片/视频素材， 通过连接线把它们串成镜头序列，最终导出可在专业剪辑软件中继续编辑的 FCPXML / EDL。

技术栈：React + Zustand + React Flow (@xyflow/react) + Vite
入口：src/routes/index.tsx
状态：src/store/canvasStore.ts
心智模型 本轮迭代 节点系统 时间线 连接关系 导出 验收

01产品定位与心智模型

如果只剩五分钟讲清楚产品，请讲下面这张图。整个产品只有三层抽象， 其余所有功能都在这三层上演绎。

素材 → 边（绑定） → 镜头（Shot，住在 Timeline 里）
Layer 1 素材节点

Media Node。承载内容本身——一张图、一段视频、未来的一段文本/音频。它不知道自己将在哪个镜头被使用。

Layer 2 连接边

Edge。一条"素材 → 镜头"的可视化绑定。颜色与目标 Shot 一致，是用户理解"这段视频从哪来"的唯一锚点。

Layer 3 时间线 / 镜头

Timeline & Shot。承载时序。每个 Shot 是时间轴上的一个"格子"，引用一个素材并定义其在片中的时长与起止。

关键判断： 同一个产品的功能多数都能被这张图覆盖。新增功能前先问自己——它属于第几层？它和这三个抽象的关系是什么？

02本轮迭代 · 我们要改的 4 件事

以下是这次对齐会的核心。每件事都给了"现状 → 目标 → 验收"。 改完之后整个产品的体验会顺畅很多。

P0 · 修复 ① 时间线渲染真实数据，不再是 Mock
用户故事： 我新建几个视频节点合并到时间线，时间线里出现的应该是我的视频， 而不是开发预置的"开场 / 主场景 / 收束"。
现状

TimelineNode.tsx 内部硬编码了 INITIAL_CLIPS（三个"古风"色卡）， UI 永远渲染这三块。
store 里其实有真数据 data.shots[]，但渲染层根本不读它。

目标

删除 INITIAL_CLIPS，clips 完全由 data.shots 渲染： 标题来自 shot.name，时长来自 shot.duration， 缩略图来自 shot.thumbnail，颜色来自 shot.color。

验收

  • 空画布把 mockData.ts 的 initialNodes 清空后，应用打开是干净的画布，不再出现预置的"古风短片"。
  • 动态联动添加 N 个视频 → 多选合并 → 时间线里出现 N 个 Shot，缩略图、时长、顺序完全来自这些视频。
  • 退化态data.shots 为空时，时间线显示空状态提示，不再绘制死的三个色卡。
P0 · 明确 ② 创建时间线的两条路径 + 连接线必须可见
用户故事： 我有两种习惯—— 要么先生成好素材再把它们串起来（A 路径）， 要么先建一条空时间轴再往里填素材（B 路径）。两种都要能走通， 而且必须看得到"素材属于哪个镜头"的连接线。
路径 A · 自动串联

触发条件

用户在画布上多选 ≥2 个素材节点（image / generateImage / generateVideo）。

系统行为

  1. 浮出 CTA顶部弹出"合并到时间轴"胶囊（MultiSelectionCTA）。
  2. 排序按节点 x 坐标从左到右、同列按 y 排（已实现）。
  3. 建时间线在选区下方生成 Timeline，宽度按数量自适应。
  4. 建 Shot每个素材生成一个 Shot，继承时长与缩略图。
  5. 建 Edge为每个素材→Timeline 创建一条带颜色的边。
路径 B · 手动连接

触发条件

用户从左栏添加一个空 Timeline 节点，或想往现有 Timeline 追加。

系统行为

  1. 拖线从素材底部端口拖一条线到 Timeline 节点。
  2. 松手判定onConnect 或 onConnectEnd 检测到目标是 timeline。
  3. 追加 Shot调用 addNodeToTimeline，在末尾追加。
  4. 建 Edge同样创建一条带颜色的连接线。
不可破的约束： 任何"素材 → Shot"的绑定，必须在画布上显式画出一条带颜色的连接线。 颜色与目标 Shot 在 Timeline 内的色卡颜色一致。无连接线 = 用户无法理解片段来源 = 功能失效。
P1 · 优化 ③ 节点连接端口语义化：横向 = 处理流，纵向 = 编辑流
用户故事： 未来视频节点可能要连"风格转换"、"加字幕"、"抽帧"等处理节点（横向）； 同时还要连到时间线做剪辑（纵向）。如果所有线都从右侧出，必然会打架。

改动点

  • 视频节点 GenerateVideoNode.tsx 目前只有右侧 id="out"。 需要新增一个底部端口 id="source-timeline"（橙色胶囊，左偏 ~70%）， 原右侧端口改名 source-process 表示"接其他处理节点"（保留，暂未使用）。
  • 图片节点 ImageNode.tsx / GenerateImageNode.tsx 已经有 bottom 端口（橙色）， 本次只需对齐视频节点。
  • 连接逻辑 mergeSelectionToTimeline / addNodeToTimeline 创建 Edge 时， sourceHandle 设为 source-timeline。
设计原则一句话： 横向走"处理"（素材 → 素材的处理结果），纵向走"编辑"（素材 → 时间线）。 用户不需要解释也能看懂。
P2 · 隐藏 ④ 空 Shot 功能逻辑保留，UI 入口暂时隐藏
背景： store 里 addShot 函数可以创建一个未绑定素材的空槽位（status=empty）。 这是一种"专业剪辑师"工作流——先排时序再填素材。MVP 阶段不暴露，避免普通用户困惑。
  • 保留store 的 addShot 函数、Shot 类型里的 status: "empty" 状态保持不变。
  • 隐藏UI 上找不到"新增空 Shot"的按钮/菜单项/快捷键。
  • 容错若数据中意外出现 empty 状态的 Shot，仍能正常渲染为灰色占位，不要崩。

05时间线与镜头

时间线本质是一个容器，里面装着若干 Shot（镜头）。整个产品的"时序"概念都在 Shot 上。

Shot 数据模型

interface Shot {
  id: string;              // 唯一 ID
  name: string;            // 显示名（可在属性面板编辑）
  index: number;           // 在 Timeline 中的顺序
  duration: number;        // 在片中的时长（秒）
  sourceIn: number;        // 源素材入点（秒）
  sourceOut: number;       // 源素材出点（秒）
  bindings: string[];      // 绑定的素材节点 ID 列表
  thumbnail?: string;      // 缩略图 URL（来自素材）
  color: "cyan" | "purple" | "yellow" | "gray";
  status: "empty" | "ready" | "generating" | "failed";
}

Shot 状态机

● empty · 未绑定素材的占位 ● ready · 已绑定，可导出 ● generating · AI 生成中 ● failed · 生成失败

本轮迭代 empty 不暴露 UI 入口；generating / failed 当前未在 UI 中区分渲染（待补）。

Timeline 容器属性

  • width画布上 Timeline 的总宽（默认 1200 / Mock 1800）
  • pxPerSecond每秒对应像素数（默认 60），决定 clip 在轨道上的宽度
  • shotsShot 数组，顺序即播放顺序

Timeline 头部操作（按钮已在 UI，多数未联动）

▶ 播放/暂停 📥 导出 ✂️ 裁剪 🔍 搜索 🧲 吸附 🔒 锁定 ＋ 添加 字幕 / 特效 / 音乐

本期不要求都实现，但 UI 已经画好，开发同学心里有数即可。

06连接关系（两条路径详解）

画布上任何"素材 → 时间线"的关系都通过 Edge 表达。所有 Edge 都有颜色，颜色与目标 Shot 一致。

Edge 数据模型

interface Edge {
  id: string;              // 唯一 ID
  from: string;            // 源节点 ID（素材）
  to: string;              // 目标 ID（Timeline 节点 ID 或 Shot ID）
  toHandle?: string;       // 目标端口（Shot ID）
  color?: string;          // 边颜色，与 Shot color 一致
}

路径 A：自动串联

  1. 用户操作在画布上按住框选或 Shift 多选 ≥2 个素材节点。
  2. 触发 UI顶部浮出 MultiSelectionCTA 胶囊："已选中 N 个素材 · 合并到时间轴"。
  3. 用户确认点击胶囊里的 CTA。
  4. store 行为调用 mergeSelectionToTimeline(nodeIds)：
    • 过滤出 media 类型节点，按 x（次 y）排序
    • 在选区下方位置新建 Timeline 节点
    • 为每个素材创建一个 Shot，继承 duration 和 src 作为 thumbnail
    • 为每个素材 → Timeline 创建一条 Edge，颜色按素材类型映射
    • 选中新建的 Timeline，打开属性面板

路径 B：手动连接

  1. 用户操作从左栏添加一个空 Timeline 节点（也可以从已有 Timeline 继续追加）。
  2. 用户拖线从素材节点的底部 source-timeline 端口拖一条线，松手在 Timeline 节点上。
  3. React Flow 回调onConnect 检测到目标是 timeline，直接转发到 store； 若用户拖到空白处但鼠标停在 Timeline 卡片上，onConnectEnd 通过 document.elementsFromPoint 兜底识别。
  4. store 行为调用 addNodeToTimeline(nodeId)：
    • 取最新创建的 Timeline（若无，则新建一个，把当前素材作为第一个 Shot）
    • 在末尾追加 Shot，继承 duration / thumbnail
    • 创建带颜色的 Edge，toHandle 指向新 Shot ID

右键菜单的补充路径

在素材节点上右键 → "加入到最近的时间轴 / 新建时间轴并加入"。 与路径 B 行为一致，只是入口不同（适合手不离右键的用户）。

三条路径，一个出口： 不论用户走 A / B / 右键，最终都落到 store 的两个函数： mergeSelectionToTimeline（批量）/ addNodeToTimeline（单个）。 Edge 创建逻辑统一，保证视觉一致。

09状态管理与数据模型

全局状态用 Zustand（src/store/canvasStore.ts）。所有的写操作都先 pushHistory() 入栈，支持 50 步撤销/重做。

核心状态字段

{
  projectName: string;                  // 顶部标题
  nodes: CanvasNode[];                  // 所有节点（含 timeline）
  edges: Edge[];                        // 所有连接边
  selectedId: string | null;            // 选中的节点 ID
  selectedShotId: string | null;        // 选中的 Shot ID
  panelOpen: boolean;                   // 属性面板开关
  exportOpen: false | "fcpxml" | "edl"; // 导出弹窗类型
  contextMenu: ContextMenuState | null; // 右键菜单位置
  past: Snapshot[];  future: Snapshot[];// 撤销栈
}

关键 Action

  • addNode从左栏添加一个节点（image / generateImage / generateVideo / timeline）
  • removeNode删除节点，同时清除指向它的所有 Edge
  • addEdge通用边创建。若目标是 Shot，自动调用 bindNodeToShot
  • mergeSelectionToTimeline路径 A 核心：批量素材 → 新 Timeline + Shots + Edges
  • addNodeToTimeline路径 B 核心：单个素材追加到最近 Timeline 末尾（无则新建）
  • bindNodeToShot把素材绑定到特定 Shot（更新 bindings / color / thumbnail / status）
  • addShot / removeShot / updateShot / reorderShotsShot 的增删改 + 排序
  • undo / redo基于 Snapshot 的撤销栈
