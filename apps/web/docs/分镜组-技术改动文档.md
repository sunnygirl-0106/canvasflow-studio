## 1. 数据结构改动（`store/canvasStore.ts`）

### 1.1 新增节点类型

```ts
// 旧
export type NodeKind = "image" | "generateImage" | "generateVideo" | "composition" | "audio";
// 新
export type NodeKind =
  | "image" | "generateImage" | "generateVideo" | "composition" | "audio"
  | "group"        // 普通组（最小实现，仅作为转换中转，见 §3.6）
  | "storyboard";  // 分镜组容器
```

### 1.2 分镜组数据模型

分镜组是一个**容器节点**：对外是一个可整体移动/复制/连线的 `CanvasNode`，对内持有一组「宫格 + 图像引用」。沿用现有 `CanvasNode { id, kind, x, y, data }` 结构，新增 `data.storyboard` 字段：

```ts
export type AspectRatio = "21:9" | "16:9" | "9:16" | "3:4" | "4:3" | "1:1";

export interface StoryboardCell {
  id: string;
  /** 行列定位，1-based。序号文案即 `${row}-${col}` */
  row: number;
  col: number;
  /** 该格承载的图像源；空格为 undefined */
  src?: string;
  /** 该图像对应的原始画布节点 id（解组/转普通组时还原用）。空格为 undefined */
  sourceNodeId?: string;
  name?: string;
}

export interface StoryboardData {
  rows: number;
  cols: number;
  ratio: AspectRatio;
  /** 序号角标开关，默认 false */
  showIndex: boolean;
  /** 行优先填充的宫格数组，长度恒为 rows*cols（空位用空 cell 占位） */
  cells: StoryboardCell[];
}

export interface CanvasNode {
  id: string;
  kind: NodeKind;
  x: number;
  y: number;
  data: {
    // ……既有字段保持不变
    src?: string;
    name?: string;
    duration?: number;
    width?: number;
    pxPerSecond?: number;
    tracks?: Track[];
    waveform?: string;
    shots?: Clip[];
    /** 新增：分镜组数据，仅 kind==="storyboard" 时存在 */
    storyboard?: StoryboardData;
    /** 新增：普通组成员 id 列表，仅 kind==="group" 时存在（见 §3.6） */
    memberIds?: string[];
  };
}
```

> 约定：`cells` 始终按**行优先**顺序排列且长度 = `rows*cols`；空格也占一个 `StoryboardCell`（无 `src`）。这样布局/渲染/序号/reflow 都可以用纯下标运算，避免稀疏结构带来的边界 bug。

### 1.3 常量

```ts
export const STORYBOARD_PRESETS = [2,3,4,5]; // 2x2 / 3x3 / 4x4 / 5x5

```


## 2. 纯函数层（新建 `lib/storyboard.ts`）

把所有「无副作用的布局/排序/合成计算」抽到这里，store action 只负责拼装与写状态，便于单测。

### 2.1 自动宫格布局（PRD 5.1）

```ts
/** N 张图 → 接近正方形、尽量填满的行列 */
export function autoGrid(n: number): { rows: number; cols: number } {
  const cols = Math.ceil(Math.sqrt(n));
  const rows = Math.ceil(n / cols);
  return { rows, cols };
}
// N=9→3x3, N=6→2x3(行2列3), N=4→2x2, N=12→3x4
```

> 注：PRD 文字示例写「6→3x2(3列2行)、12→4x3」，与 `cols=ceil(sqrt)` 推导出的 `2x3 / 3x4` 行列数一致（都是 3 列 2 行 / 4 列 3 行），仅「行x列」写法顺序不同。**统一以「行 rows × 列 cols」为内部表示**，UI 文案展示按 `rows×cols`。

### 2.2 填充与 reflow（PRD 5.2）

```ts
/** 把有序图像源填入 rows*cols 宫格，按行优先；返回定长 cells（空位占位） */
export function fillCells(items: {src:string; sourceNodeId:string; name?:string}[], rows: number, cols: number): StoryboardCell[];

/** 改变行列后重排：返回 { cells, overflow }。overflow 为容量不足时被挤出的图像源（供解组到右侧） */
export function reflow(prev: StoryboardData, rows: number, cols: number): { cells: StoryboardCell[]; overflow: {src:string; sourceNodeId:string; name?:string}[] };
```

- **增加宫格**：原图像顺序不变填入前面，多出的格为空 `cell`。
- **减少宫格**：超过 `rows*cols` 的图像进 `overflow`，由 store 在分镜组右侧重建为独立 `image` 节点（不丢失）。

### 2.3 序号与几何

```ts
export const cellLabel = (cell: StoryboardCell) => `${cell.row}-${cell.col}`;
/** 由 ratio 求单格宽高（用于画布渲染与拼接画布尺寸） */
export function cellSize(ratio: AspectRatio, baseW: number): { w: number; h: number };
```

### 2.4 拼接合成（PRD 5.5，演示级）

```ts
/**
 * 用离屏 <canvas> 把所有非空 cell 按宫格平铺成一张大图，导出 dataURL。
 * - resolution: 2K=2560 宽 / 4K=3840 宽（高按 rows*ratio 推导）
 * - 源图宽 < 目标分辨率 → drawImage 直接拉伸放大（演示「强制放大」，不接 AI 高清）
 * - showIndex 为真时，在每格右下角绘制 `${row}-${col}` 角标
 * 返回 dataURL；失败（如跨域图无法读取）时回退占位图，保证演示不崩。
 */
export async function stitchToDataURL(sb: StoryboardData, resolution: "2K"|"4K"): Promise<string>;
```

> 演示注意：`picsum.photos` 等跨域图直接 `drawImage` 可能触发 canvas 污染导致 `toDataURL` 抛错。演示级做法：给离屏 `<img>` 设 `crossOrigin="anonymous"`，失败则降级为「灰底 + 网格 + 序号」的占位拼接图，并在 UI toast 提示「演示环境拼接为占位图」。

## 3. Store action 实现要点（`store/canvasStore.ts`）

所有写操作开头调用 `get().pushHistory()`，复用既有 undo/redo。下列只列与既有范式不同的关键点。

### 3.1 `mergeToStoryboard(nodeIds)` —— 入口一

参考既有 `mergeToComposition` 的过滤/排序范式：

1. 过滤出图像类节点：`MEDIA_KINDS = ["image","generateImage","generateVideo"]` 中的图像（演示中以 `image` 为主；非图像节点直接剔除，见默认取值①）。
2. `picked.sort((a,b)=> a.y - b.y || a.x - b.x)`（从上到下、从左到右，符合宫格阅读顺序；既有 merge 用 `x||y`，这里改为 `y||x` 更贴分镜阅读序）。
3. `picked.length < 2` → 返回 `null`，不创建（最小张数=2，见默认取值①）。
4. `const {rows,cols} = autoGrid(picked.length)`；`cells = fillCells(...)`。
5. 新建 `storyboard` 节点：位置放在所选图像**右侧**（`x = maxX + 400`，纵向居中），`data.storyboard = { rows, cols, ratio: DEFAULT_RATIO, showIndex:false, cells }`。
6. **被并入的原始图像节点**：演示期建议**从画布移除**（其内容已进容器），并把它们与外部的连线一并移除；`sourceNodeId` 仍记录原 id 以便解组还原。
7. `set` 后 `selectedId = 分镜组id`，触发顶 bar 浮现。

### 3.2 `convertGroupToStoryboard(groupId)` —— 入口二

- 仅当 `group` 节点 `memberIds` 全为图像节点才执行（否则入口在 UI 层置灰，见 §4.1/§3.6）。
- 按 `memberIds` 原顺序 `fillCells`，`autoGrid(members.length)`，其余同 §3.1。
- 移除原 `group` 节点。

### 3.3 `createStoryboardFromCells(cells, rows, cols)` —— 入口三

- 「宫格切分」工具本期**不在范围内**（PRD 入口三依赖既有/外部切分能力）。本 action 只提供「拿到一组带 row/col 的切片 → 组装分镜组」的能力，供切分工具回调。
- 切片自带 `row-col`，直接构造 `StoryboardData`，`showIndex` 默认按截图 image(19) 设为 `true`。
- 若本期暂不实现切分 UI，可仅保留 action + 单测，入口三在前端先隐藏。

### 3.4 `setStoryboardGrid(id, rows, cols)` —— 增减宫格

```ts
setStoryboardGrid: (id, rows, cols) => {
  rows = clamp(rows, 1, STORYBOARD_MAX); cols = clamp(cols, 1, STORYBOARD_MAX);
  get().pushHistory();
  const sb = getStoryboard(id);
  const { cells, overflow } = reflow(sb, rows, cols);
  // 溢出图像：在分镜组右侧重建为独立 image 节点（不丢失）
  const overflowNodes = overflow.map((o, i) => makeImageNode(o, sbRightX + i*offset, sbY));
  set(...);  // 更新分镜组 cells/rows/cols + 追加 overflowNodes
}
```

### 3.5 `setStoryboardRatio` / `toggleStoryboardIndex`

- `setStoryboardRatio`：仅改 `ratio`，整组同步；图像在渲染层用 `object-fit: contain`（**留边**，见默认取值④）适配，不裁切像素。
- `toggleStoryboardIndex`：翻转 `showIndex`，仅影响角标与拼接渲染，不动 `cells` 顺序。

### 3.6 `convertStoryboardToGroup` / `ungroupStoryboard` 与「普通组」最小定义

- **普通组 `group`（最小实现）**：`kind:"group"`，`data.memberIds: string[]`，无强制对齐。本期它只作为「转普通组 ↔ 转分镜组」的中转容器，画布上渲染为一个虚线包围框（可后续完善）。
- `convertStoryboardToGroup(id)`：把非空 cell 还原为独立 `image` 节点（按宫格顺序在容器原位平铺），新建 `group` 节点 `memberIds=[新节点ids]`，移除分镜组。
- `ungroupStoryboard(id)`：把非空 cell 还原为**完全独立**的 `image` 节点（不建 group），移除分镜组。
- 还原节点优先用 `sourceNodeId` 复原 id 与既有外部连线；若原节点在 §3.1 已删除，则新建并丢失原连线（演示可接受）。

### 3.7 `stitchStoryboard(id, resolution)`

- `await stitchToDataURL(sb, resolution)` → 新建一个 `image` 节点（`src=dataURL`，`name="分镜拼接图"`），放分镜组下方/右侧，`selectedId` 切到新节点。**不改动原分镜组**（PRD 5.5：输出新图、不破坏原组）。

### 3.8 `duplicateStoryboard(id)`

- 深拷贝分镜组 `data.storyboard`，生成新 id 与 cell id，位置偏移。
- 连线：复制**内部**及**与外部节点**的连线（默认取值③：一并复制）。对每条 `edge.from===id || edge.to===id` 生成指向新分镜组的副本。

### 3.9 `clearStoryboard(id)` / 删除

- `clearStoryboard`：把所有 cell 置空（`src/sourceNodeId=undefined`），保留空容器与 `rows/cols/ratio`；同时移除被清空图像相关连线。**调用方（顶 bar）必须先弹二次确认**（默认取值②）。
- 删除分镜组：复用 `removeNode(id)`（已联动删除其连线），但右键/快捷键删除前**需二次确认**（默认取值②）。

## 5. 状态流转（实现校验用）

```
独立图像节点 ──mergeToStoryboard / Cmd+Alt+G──► 分镜组
普通组(纯图像) ──convertGroupToStoryboard──► 分镜组
宫格切分结果 ──createStoryboardFromCells──► 分镜组

分镜组 ──convertStoryboardToGroup──► 普通组(按宫格顺序)
分镜组 ──ungroupStoryboard──► 独立图像节点(完全独立)
分镜组 ──setStoryboardGrid(减少)──► 分镜组 + 右侧溢出独立节点
分镜组 ──clearStoryboard──► 空分镜组容器
分镜组 ──stitchStoryboard──► 原分镜组(不变) + 新拼接图节点
分镜组 ──duplicateStoryboard──► 原分镜组 + 副本(含内/外连线)
```

每个箭头对应一个 action + 一条单测（见 §7）。

## 6. 边界与异常处理（对应 PRD §6，已按默认取值定稿）

| 编号 | 处理 |
|---|---|
| E-1 框选含非图像节点 | 过滤剔除，仅图像参与；非图像保留在画布外（默认取值①） |
| E-2 普通组混非图像 | 不显示「转分镜组」入口（§4.1） |
| E-3 仅 1 张图 | 不创建，最小张数=2（默认取值①） |
| E-4 减少宫格溢出 | 溢出图像 reflow 到分镜组右侧为独立节点，不丢失（§3.4） |
| E-5 清空 | 二次确认弹窗 → 删内部图像与连线，保留空容器（§3.9） |
| E-6 拼接源图不足 | 强制拉伸放大 + UI 明确提示（§2.4/§4.3） |
| E-7 删除分镜组 | 需二次确认（默认取值②） |
| E-8 副本连线 | 内部 + 外部连线一并复制（默认取值③） |
| E-9 空分镜组 | 允许存在，可继续拖入图片填充空格 |

## 8. 默认取值（PRD 第 9 节 6 个待确认问题 · 定稿）

| # | 待确认问题 | 定稿取值 |
|---|---|---|
| ① | 非图像节点 / 最小张数 | 非图像节点**不支持**本功能（创建时过滤剔除）；**单张图片不创建分镜组**，最小 2 张 |
| ② | 删除是否二次确认 | **需要二次确认**（清空与删除分镜组均弹确认弹窗） |
| ③ | 副本与外部连线 | 创建副本时**内部 + 外部连线一并复制** |
| ④ | 比例切换裁切策略 | **留边**（`object-fit: contain` 适配，不裁切像素） |
| ⑤ | 单格操作（替换/换位/删除） | 本期仅**支持拖拽换位**；单格替换/删除暂不做 |
| ⑥ | 行列上限 | **设上限**，`STORYBOARD_MAX = 10`（最大 10×10） |

> 其余未列能力（如普通组的完整交互、宫格切分 UI、真实图像高清化）本期不做，留待后续迭代。
