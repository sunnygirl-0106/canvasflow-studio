# 视频合成 · 多轨编辑技术改动文档

> 状态：已评审，待实施。本文是**可直接交给 Claude Code 执行**的改动方案。
> 配套文档：《多轨编辑-功能需求文档.md》。需求层结论以本文"决策锁定"为准。
> 适用范围：CanvasFlow 演示仓库（前端 demo，无后端、无持久化）。

---

## 0. 决策锁定（评审结论）

| # | 议题 | 结论 |
|---|---|---|
| 1 | V2（叠加轨）片段排布 | **自由摆放**（带 `startSec`，可有空隙） |
| 2 | 向后兼容 | **一次性迁移、不留兼容层**（`initialNodes` 为空、无持久化，直接把 `shots` 改为 `tracks`） |
| 3 | 新增视频轨入口 | **拖出自动建轨**（把片段拖到 V1 上/下方空白区，自动创建 V2 并落入；已满 2 轨则回弹） |
| 4 | 音频拖入方式 | **方式一：连线汇入合成**（音频节点连入"视频合成"节点 → 自动生成音频片段，类比现有视频逻辑） |
| 5 | 同轨/跨轨重叠 | **同轨不允许重叠**（自动避让/回弹），**跨轨允许重叠** |
| 6 | 音频音量 | **只做二态：有声 / 无声（静音）**，不做数值音量滑杆 |
| 7 | V2 预览呈现 | **画中画小窗**（叠加在 V1 之上，固定位置/尺寸） |
| 8 | 多音频混音 | **以可视化为主**（时间轴随播放头推进、静音状态可见）；真实出声为可选项，不作硬性要求 |
| 9 | 静音控制粒度 | **全局静音**（保留现有全局静音按钮；不做轨级静音）。注：片段级"有声/无声"见 #6，与全局静音并存 |
| 10 | 视频区/音频区分组标题 | **不加** |

---

## 1. 总体方案

把合成节点的数据从扁平 `shots: Shot[]`（单视频轨）升级为 `tracks: Track[]`（多轨）。轨道分两类：

- **视频轨**：最多 2 条。`V1` 主轨（首尾相接、顺排），`V2` 叠加轨（自由摆放）。预览时 V2 以画中画小窗叠加在 V1 上。
- **音频轨**：不限条数。片段从画布音频节点连线汇入，自由摆放、可跨轨重叠。

核心新增字段是片段的 **`startSec`（时间轴起始秒）**；多轨下不能再靠"前面片段累加"推位置。

因为 `src/data/mockData.ts` 的 `initialNodes = []` 且无持久化，**不需要数据迁移脚本**——只要把"运行时创建合成节点"的逻辑（`mergeToComposition` / `addToComposition`）改为产出 `tracks`，并把所有读 `shots` 的消费方改为读 `tracks` 即可。

## 2. 数据模型改动 · `src/store/canvasStore.ts`

### 2.1 类型定义

将 `Shot` 重命名/扩展为 `Clip`（保留 `Shot` 作为别名以减少改动面也可，但建议直接改名为 `Clip`，更贴语义）。新增 `Track`。

```ts
export type NodeKind = "image" | "generateImage" | "generateVideo" | "composition" | "audio"; // 新增 audio
export type ShotStatus = "empty" | "ready" | "generating" | "failed";
export type TrackKind = "video" | "audio";

// 原 Shot → Clip（字段全部保留，新增 startSec / clipKind / muted）
export interface Clip {
  id: string;
  name: string;
  index: number;          // 轨内顺序索引
  startSec: number;       // 【新增】在整条时间轴上的起始秒
  duration: number;
  baseDuration: number;
  speed: number;
  sourceIn: number;
  sourceOut: number;
  bindings: string[];
  thumbnail?: string;     // 视频缩略图 / 音频波形图
  color: "cyan" | "purple" | "yellow" | "rose" | "emerald" | "gray";
  status: ShotStatus;
  clipKind: TrackKind;    // 【新增】"video" | "audio"
  muted?: boolean;        // 【新增·仅音频】二态：true=无声
}

export interface Track {
  id: string;
  kind: TrackKind;        // "video" | "audio"
  name: string;          // "V1" | "V2" | "A1" | "A2" ...
  clips: Clip[];
}

export interface CanvasNode {
  id: string;
  kind: NodeKind;
  x: number;
  y: number;
  data: {
    src?: string;
    name?: string;
    duration?: number;
    width?: number;
    pxPerSecond?: number;
    tracks?: Track[];     // 【替换】原 shots?: Shot[]
    waveform?: string;    // 【新增·音频节点】波形预览
  };
}
```

> 兼容提示：若想减少一次性改动量，可临时 `export type Shot = Clip;` 作为过渡别名；但 `data.shots` 字段应直接改为 `data.tracks`，不保留双写。

### 2.3 派生计算（替换原 totalDuration / 单轨假设）

新增工具函数（可放本文件或 `src/lib/`）：

```ts
// 单个片段在时间轴上的结束时间
export const clipEnd = (c: Clip) => c.startSec + c.duration;

// 单条轨的时长
export const trackDuration = (t: Track) =>
  t.clips.reduce((max, c) => Math.max(max, clipEnd(c)), 0);

// 合成节点总时长 = 所有轨中最大的结束时间
export const compDuration = (tracks: Track[]) =>
  tracks.reduce((max, t) => Math.max(max, trackDuration(t)), 0);
```

`V1` 主轨"顺排"时 `startSec` 由顺序推导（见 2.5 的规范化函数）。

### 2.4 State 接口改动（action 增删）

删除/改写依赖 `shots` 的旧 action，新增多轨 action：

```ts
interface State {

  updateClip: (compId: string, clipId: string, patch: Partial<Clip>) => void;
```

### 2.5 关键 action 实现要点

**规范化 V1 主轨（顺排去空隙）** —— 任何改动 V1 后调用：

```ts
function normalizeSequential(track: Track): Track {
  let cursor = 0;
  const clips = track.clips
    .slice()
    .sort((a, b) => a.startSec - b.startSec)
    .map((c, i) => {
      const next = { ...c, startSec: cursor, index: i };
      cursor += c.duration;
      return next;
    });
  return { ...track, clips };
}
```

**moveClip（跨轨/同轨核心）**：
- 找到源轨、目标轨、片段。
- 从源轨移除，加入目标轨。
- 若目标轨是 **V1 主轨** → 设置 `startSec` 后 `normalizeSequential`（顺排）。
- 若目标轨是 **V2 / 音频轨** → 直接用 `toStartSec`（自由摆放），但需做**同轨防重叠**（决策 #5）：若与目标轨已有片段时间重叠，吸附到最近的空隙边缘；找不到则回弹（不落下，操作取消）。
- `clip.clipKind` 必须与目标轨 `kind` 一致：视频片段不能进音频轨，反之亦然 → 不一致直接拒绝。
- 调 `pushHistory()`。

**同轨重叠检测**：
```ts
function overlaps(a: Clip, b: Clip) {
  return a.startSec < clipEnd(b) && b.startSec < clipEnd(a);
}
```

**addVideoTrack**：
```ts
// 已有视频轨数 >= MAX_VIDEO_TRACKS 时：不创建，触发提示 toast（见 §8）
```

**addAudioClipFromNode（方式一）**：
- 取 `nodeId` 音频节点的 `data`（name/duration/waveform/src）。
- 选目标音频轨：默认最后一条音频轨；若没有音频轨则先建 A1。
- `startSec` 默认取 `atSec ?? 0`（或该轨末尾，避免与现有片段重叠）。
- 生成 `Clip{ clipKind:"audio", muted:false, color:"gray"|按序, ... }` 追加。
- `pushHistory()`。

### 2.6 创建合成节点的改动（`mergeToComposition` / `addToComposition`）

把现在生成 `data.shots` 的地方改为生成 `data.tracks`：

```ts
// merge：多段视频 → 一个合成节点，落在 V1 主轨顺排
data: {
  name: ...,
  width: ...,
  pxPerSecond: 60,
  tracks: [
    {
      id: `track-v1-${ts}`,
      kind: "video",
      name: "V1",
      clips: picked.map((n, i) => ({
        id: `clip-${ts}-${i}`,
        name: ...,
        index: i,
        startSec: /* 由 normalizeSequential 累加，初始可填 0 后规范化 */,
        duration: dur, baseDuration: dur, speed: 1,
        sourceIn: 0, sourceOut: dur,
        bindings: [n.id], thumbnail: n.data.src,
        color: colorByIndex(i), status: "ready",
        clipKind: "video",
      })),
    },
  ],
}
// 生成后对 V1 调用 normalizeSequential 修正 startSec。
```

`addToComposition`：
- 若被加入的是**视频节点** → 追加到 V1 主轨并 `normalizeSequential`。
- 若被加入的是**音频节点**（`node.kind === "audio"`）→ 走 `addAudioClipFromNode`（追加到音频轨，没有则建 A1）。

### 2.7 `addEdge` 的分流

现有 `addEdge` 里 "if to is a shot, bind"。多轨下：当 `from` 是 `audio` 节点、`to` 是合成节点时 → 调 `addAudioClipFromNode(compId, fromNodeId)`（决策 #4 方式一）。视频节点维持现有 `addToComposition`/bind 逻辑。

### 2.8 全局静音

`CompositionEditor` 已有 `muted` 局部 state + `TrackTimeline` 的全局静音按钮 —— **保持为全局静音**（决策 #9）。不新增轨级静音。片段级 `muted`（决策 #6）独立于此，仅作用于音频片段的"有声/无声"标记。

## 3. 时间轴改造 · `src/components/composition/TrackTimeline.tsx`

当前是单轨渲染。改为多轨：

### 3.1 Props

```ts
interface Props {
  compId: string;
  tracks: Track[];          // 替换 shots
  currentTime: number;
  pxPerSec: number;
  selectedClipId: string | null;
  onSeek: (t: number) => void;
  muted: boolean;           // 全局静音
  onToggleMute: () => void;
}
```

### 3.2 布局

- 顶部 `Ruler`（保留）。刻度/网格用 `compDuration(tracks)` 计算 `contentWidth`。
- 轨道区按顺序渲染：先所有 `kind==="video"` 轨（V1、V2），再所有 `kind==="audio"` 轨（A1、A2…）。**不加分组标题/分隔线**（决策 #10），但视频轨与音频轨可用轻微底色区分。
- 轨道区整体**纵向可滚动**（音频轨多时）；横向滚动与 ruler/playhead 联动（保留现有 `containerRef` 横向滚动）。
- 播放头（`playheadX`）高度改为覆盖 **Ruler + 所有轨道总高**。
- `SIDEBAR_W` 左侧栏：每条轨一行轨道头（轨名 V1/V2/A1…；音频轨带"删除轨"按钮；底部放"+ 视频轨""+ 音频轨"入口）。全局静音按钮保留在侧栏顶部或播放控制区。

### 3.3 片段定位（核心变化）

废弃 `layoutShots` 的累加游标，改为按 `startSec` 直接定位：

```ts
const clipX = (c: Clip) => TRACK_PAD_LEFT + c.startSec * pxPerSec;
const clipW = (c: Clip) => c.duration * pxPerSec;
```

### 3.4 拖动逻辑（替换 `handleClipDragStart`）

统一为 `moveClip` 驱动，支持纵向命中不同轨：

- 拖动中：记录鼠标在轨道区的 `(x, y)`；
  - 由 `y` 命中目标轨（按各轨纵向区间）。
  - 由 `x` 反推 `toStartSec = round((x - offset - TRACK_PAD_LEFT)/pxPerSec, 0.1)`，并做吸附（刻度/播放头/相邻边缘）。
- **拖出自动建轨（决策 #3）**：若视频片段被拖到视频区上/下方的空白带且当前只有 1 条视频轨 → 创建 V2 并落入；已有 2 条视频轨则回弹。
- **跨轨类型校验**：视频片段只能落视频轨、音频片段只能落音频轨，否则回弹。
- **同轨防重叠（决策 #5）**：落点在目标轨与现有片段重叠 → 吸附到空隙；V1 主轨落下后 `normalizeSequential`。
- 落点指示（`dropIndicator`）扩展为"目标轨 + 目标 x"的二维提示。

### 3.5 片段渲染

- 视频片段：沿用现有缩略图平铺 + 名称 + 时长样式。
- 音频片段：显示**波形**（`clip.thumbnail`/`waveform`，demo 可用伪波形 SVG/静态图）+ 名称 + 时长；右上角一个**静音切换图标**（决策 #6，二态 `muted`）。
- 选中态、resize 手柄（左右裁剪）沿用现有实现，作用于 `updateClip`。

## 5. 预览改造 · `PreviewStage.tsx` 与 `FullscreenPlayer.tsx`

命中逻辑从"shots 累加"改为"按轨按 `startSec` 命中"：

```ts
// 取某条轨在 t 时刻的活动片段
function clipAt(track: Track, t: number): Clip | null {
  return track.clips.find(c => t >= c.startSec && t < clipEnd(c)) ?? null;
}
```

- 取 `V1 = tracks.find(k==="video" && name==="V1")`（或视频轨数组第 0 条），底图 = `clipAt(V1, t)?.thumbnail`。
- 取 `V2 = 视频轨数组第 1 条`（若存在），`v2Clip = clipAt(V2, t)`：若存在则**画中画小窗叠加**（决策 #7）——固定位置（建议右上角）、固定尺寸（如父容器宽的 28%），`object-cover`，带细边框/圆角。
- 若只有一轨有画面则只显示该轨。
- 音频：**可视化为主**（决策 #8）。预览区不强制出声；可选地对未静音的音频片段用 `<audio>` 简单播放（非硬性要求，建议作为 stretch，先不接）。
- `FullscreenPlayer` 同步同样的 V1 底图 + V2 画中画逻辑。
