## 一、背景与目标

### 1.1 背景

CanvasFlow 当前已具备图片、视频、视频合成、音频、分镜组等节点，能把"素材"在画布上成组、对齐、合成。但从 **0 到 1 的"内容编排"** 环节仍然是空白：用户手里只有一段剧情 / 剧本时，要把它拆成一镜一镜、再为每一镜写画面描述、景别、运镜、对白、提示词，全靠人工，既慢又容易遗漏。

短剧、广告、AI 影视创作者真正的起点，往往是**一段文字**。他们需要的是：把这段文字喂进来，一次性得到一张结构化的**分镜脚本表**，每一行就是一个镜头、字段齐全，可以直接驱动后续的批量出图与生成视频提示词。

### 1.2 功能目标

新增 **脚本节点（Script Node）**：接收一段剧本文本 + 一句简短的生成提示词，一键解析生成一张结构化的 **分镜脚本（Storyboard Script）** —— 以"一行一镜"的表格形式呈现，字段涵盖镜号、时长、画面描述、角色、景别、角色动作、情绪、场景标签、光影氛围、音效、对白、分镜提示词、视频运动提示词等。脚本支持全屏浏览、逐格编辑、卡片视图、字段可见性配置与画面筛选，并为后续"批量生成分镜图 / 视频"预留出口。

### 1.3 适用场景

- 短剧 / 广告 / 微电影的**前期分镜编排**：从剧情大纲一键成脚本。
- AI 影视：把脚本表的"分镜提示词 / 视频运动提示词"作为下游批量生成图像、视频的输入。
- 创作者把脑中一段剧情快速结构化、可视化，便于团队评审与改稿。

### 1.4 设计原则

- **一句话即可用**：用户只需粘贴剧本 + 写一句提示词，其余结构由系统补全。
- **节点即数据源**：脚本节点对外是一个可连线、可继续往后接（生成分镜图/视频）的对象；对内是一张结构化、可编辑的脚本表。
- **可读可改**：生成结果不是黑盒，所有字段都能逐格修改、增删图片、按需隐藏，让脚本越用越贴合创作者意图。
- **渐进式**：本期只做"剧本→脚本"一条路，节点形态与数据结构需为另外两种入口（角色/视频参考）预留扩展位。

### 1.5 关键认知：这不是一个纯前端功能（需求层约束）

与画布上已有的图片 / 视频 / 合成等"纯前端展示"节点不同，**脚本生成是真实调用大模型的功能**，因此在需求层就必须明确以下约束（"怎么实现"留给后续《技术改动文档》，本文不展开）：

- **必须有后端**：API Key、计费扣点、生成逻辑不能放前端（会泄露、会被刷），需由后端代理大模型调用。
- **生成 = 系统内置提示词 + 用户输入 + 剧本，三者合并喂给大模型**：用户只感知自己写的那一句简短提示词；真正让模型产出规整脚本表的是产品**预置、对用户不可见**的一套长提示词（"内功"）。
- **生成是黑盒**：用户看到的是"输入剧本 + 一句话 → 输出脚本表"。中间"扩写故事 → 拆分镜头 → 逐镜补全字段"是模型内部的思考步骤，**属于实现细节，本功能文档只规定输入与输出，不规定调用次数与编排方式**。
- **生成需要时间与反馈**：因为是真实模型调用，必须有进度 / 流式呈现、失败重试等状态（见 §8）。

## 二、名词定义

| 名词 | 定义 |
| --- | --- |
| 文本节点（Text Node） | 画布上承载纯文本的节点。本期用于粘贴 / 录入**剧本原文**，作为脚本节点的输入。 |
| 脚本节点（Script Node） | 本次新增节点。接收剧本文本 + 生成提示词，生成并承载一张**分镜脚本表**。 |
| 分镜脚本（Storyboard Script） | 脚本节点的产物：一张"一行一镜"的结构化表格，每行是一个镜头、含多个字段。 |
| 镜头 / 镜（Shot） | 脚本表中的一行，对应一个分镜镜头，由"镜号"唯一标识。 |
| 脚本视图（表格视图） | 默认视图，以表格（行=镜头，列=字段）展示全部脚本内容。 |
| 创意视图（卡片视图） | 另一种展示形态，把每个镜头渲染成一张卡片，更适合浏览画面感。 |
| 全屏视图 | 把脚本节点放大为覆盖式弹层，用于查看与编辑完整脚本。 |
| 角色列组 | 描述同一个角色的一组列：`角色N` + `角色描述N` + `角色图N`，可随角色数量横向扩展。 |
| 参考图 | 镜头级的风格 / 构图参考图像（表格中的「参考」列）。 |
| 字段可见性 | 在全屏视图中自定义"哪些列显示 / 隐藏"的配置项（对应截图工具栏的「字段」）。 |
| 筛选画面 | 按条件只展示部分镜头行的配置项（对应截图工具栏的「筛选」）。 |
| 系统内置提示词 | 产品预置、对用户不可见的一套长提示词（角色设定为"专业分镜师"、规定输出字段与规则等）。生成时与用户输入、剧本拼成完整请求发给大模型。 |
| 生成提示词（用户） | 用户在脚本节点底部输入框写的一句简短指令（如"根据剧本生成完整分镜脚本"），是用户唯一能感知到的提示词。 |

## 四、整体链路（MVP）

```
┌──────────────┐        ┌──────────────────────────────┐
│   文本节点    │  连线   │           脚本节点            │
│ （剧本原文）  │ ─────▶ │  ① 输入：剧本（来自连线）       │
│              │        │  ② 输入：一句生成提示词         │
└──────────────┘        │  ③【生成】→ 分镜脚本表格        │
                        │  ④ 全屏 / 视图切换 / 编辑       │
                        │  ⑤ 输出口 →（下游：生成分镜图/视频）│
                        └──────────────────────────────┘
```

一句话描述：**用户把剧本放进「文本节点」→ 连线到「脚本节点」→ 在脚本节点里写一句简短提示词（如"根据剧本生成一个完整的分镜脚本"）→ 点击生成 → 得到一张可编辑的分镜脚本表。**

> 两种创建入口（二选一，效果一致）：
> 1. **连线式**（主推）：先有文本节点（含剧本），把它连到新建的脚本节点。
> 2. **菜单式**：画布右键 → 添加节点 → 脚本 → 选择「剧本生成分镜脚本」，在节点内直接粘贴剧本或连入文本节点。

## 六、详细需求

### R1 · 添加节点面板（截图3）

- 「添加节点」面板新增 / 启用两项：
  - **文本**：副标题"脚本、广告词、品牌文案"。本期需把当前的占位项**落地为可用节点**——点击后在画布生成一个文本节点，支持粘贴 / 录入大段文本（剧本原文）。
  - **脚本**：带 **`Beta`** 标识，副标题建议"剧本生成分镜脚本"。点击后**不直接落节点**，而是展开右侧的二级选择卡（见 R2）。
- 位置：脚本项排在 文本 / 图片 / 视频 / 音频 之后，归入"添加节点"主分组。

### R2 · 脚本节点入口·二级菜单（截图3）

点击「脚本」后，右侧出现"尝试："引导卡，列出三种生成方式：

1. **剧本生成分镜脚本** ✅ 本期实现
2. 视频参考生成分镜脚本 ——（本期置灰 / 标注"即将上线"）
3. 角色生成分镜脚本 ——（本期置灰 / 标注"即将上线"）

- 选择「剧本生成分镜脚本」→ 在画布落一个**空的脚本节点**（待输入剧本 + 提示词）。
- 待确认：未连入文本节点时，脚本节点内是否提供一个"粘贴剧本"输入框作为兜底（建议提供，与"连线式"互为补充）。

### R3 · 连线方式（截图5）

- 文本节点从**右侧输出**，连入脚本节点**左侧输入端口**。
- 脚本节点**右侧保留输出端口**，可继续往后连"生成分镜图 / 生成视频"等下游节点。
- 待确认：脚本节点左侧是否允许同时接入多个文本节点（多段剧本合并）。MVP 建议**单输入**（一个文本节点 = 一段剧本），简化生成逻辑。

### R4 · 脚本节点形态·画布态（截图5）

画布上的脚本节点是一个**带预览的卡片**，自上而下包含：

- **悬浮工具条（卡片上方）**：`重新生成` / `生成分镜` / `下载`（导出）。
- **卡头**：左侧脚本标题（如"夏日初晴晚风"）；右侧 **视图切换下拉**（脚本视图 / 创意视图）+ **全屏按钮**。
- **卡体**：以缩略表格形式预览前若干镜头（列含 角色图 / 角色描述 / 景别 / 角色动作 等），超出部分在卡内滚动，完整内容进全屏看。
- **底部输入区**：一句话**生成提示词**输入框 + 模型选择（如 `GVLM 3.1`）+ 翻译、消耗点数、发送（生成）按钮。
  - 已连入的文本节点（剧本）以小缩略 / 引用形式显示在输入框上方，表示"已作为输入"。

### R5 · 生成（截图5）

- 用户在底部输入框写一句**简短**提示词即可，例如："根据我上传的剧本，生成一个完整的分镜脚本"。
- 点击**生成**：
  - 系统读取"已连入文本节点的剧本原文 + 这句提示词"，解析出整段故事的镜头序列，落成分镜脚本表（§7）。
  - 生成中：节点显示生成态（进度 / loading），完成后渲染表格。
- **重新生成**：保留剧本与提示词，重跑一次，覆盖当前脚本（覆盖前给二次确认，避免误删已手改内容）。
- 待确认：重新生成是否提供"保留我手动修改过的行"的选项（建议 v1 先整体覆盖，路线图再做差量）。

### R6 · 脚本视图·表格（截图1、2）

默认以**表格**呈现，**一行一镜**。字段定义见 §7。要点：

- 首列为「镜号」，按生成顺序自然递增（1、2、3…）。
- 角色相关列以**角色列组**形式出现，可随角色数量横向扩展（截图1 为单角色，截图2 为双角色 → 出现 角色2 / 角色描述2 / 角色图2）。
- 角色图 / 参考列展示缩略图；其余为文本列。
- 表格内横向、纵向均可滚动。

### R7 · 全屏视图（截图1、2）

- 点击卡头「全屏」→ 打开**覆盖式弹层**，标题栏显示脚本名 + 右上角视图下拉 + 关闭(✕)。
- 工具栏含两个入口：
  - **字段**：配置列的可见性（见 R10）。
  - **筛选**：按条件筛选镜头行（见 R10）。
- 全屏内可完整浏览并编辑所有字段（见 R8）。

### R8 · 编辑交互（截图2）

- **双击单元格**：就地进入编辑，修改文本内容，失焦 / 回车保存。
- **角色图 / 参考图**：右键弹出菜单 **「更换图片 / 删除图片」**；支持上传本地图片作为角色图或风格参考。
- 所有手动修改**即时生效**并持久化到该脚本节点的数据中（不因切换视图而丢失）。
- 待确认：是否支持新增 / 删除整行镜头、行拖拽排序（建议 v1 至少支持"删除行"，新增与排序进路线图）。

### R9 · 视图切换（截图1 顶部 Tab）

- 两种视图：**脚本视图（表格）** 与 **创意视图（卡片）**，通过卡头下拉或全屏顶部 Tab 切换。
- 创意视图：每个镜头渲染为一张卡片（突出画面描述 + 角色图 + 关键字段），便于"看画面感"。两种视图共享同一份数据，编辑互通。

### R10 · 字段可见性 + 画面筛选（截图1、2 工具栏）

- **字段（调整字段可见性）**：用户勾选 / 取消列，隐藏不关心的字段（如暂时不看"音效""光影氛围"），让脚本更简洁。隐藏只影响展示，不删除数据。
- **筛选（筛选画面）**：按条件只展示部分镜头行（如只看含某角色的镜、只看某景别）。
- 两项配置随脚本节点保存。

### R11 · 下游出口（截图5「生成分镜」）

- 脚本表生成后，「生成分镜」按钮用于把脚本**批量**转成下游的分镜图 / 视频提示词节点。
- **本期范围**：仅保留该出口与按钮位（点击后可先给"即将上线"提示，或仅落一个占位下游节点）。真正的"批量生成分镜图 / 视频"在后续迭代单独立项。

## 七、分镜脚本·字段定义

> 字段顺序与命名对齐截图 1、2 的「脚本视图」表头。角色列组随角色数量重复。

| 列名 | 含义 | 类型 | 必填 | 示例 |
| --- | --- | --- | --- | --- |
| 镜号 | 镜头序号，行唯一标识 | 数字 | 是 | `1` |
| 时长 | 该镜头预计时长（秒） | 数字 | 是 | `3` |
| 画面描述 | 这一镜画面发生了什么 | 文本 | 是 | "苏可蜷缩在沙发上，遭遇健身教练夺命连环 Call" |
| 角色N | 第 N 个出场角色名 | 文本 | 否 | "苏可" |
| 角色描述N | 角色外形 / 设定描述 | 文本 | 否 | "24 岁年轻女性，资深宅女与吃货气质，身穿灰色连帽卫衣" |
| 角色图N | 角色参考图 | 图片 | 否 | （三视图缩略图） |
| 参考 | 镜头级风格 / 构图参考图 | 图片 | 否 | （+ 上传） |
| 景别 | 镜头景别 | 枚举/文本 | 是 | "特写 / 近景 / 中景 / 全景 / 远景" |
| 角色动作 | 角色在本镜的动作 | 文本 | 否 | "惊恐地盯着前方屏幕" |
| 情绪 | 本镜情绪基调 | 文本 | 否 | "惊恐 / 视死如归" |
| 场景标签 | 场景 / 环境标签 | 文本 | 否 | "昏暗客厅 / 发光的屏幕" |
| 光影氛围 | 光线与氛围 | 文本 | 否 | "室内昏暗，手机屏幕冷光打在脸上" |
| 音效 | 声音 / 音效提示 | 文本 | 否 | "急促连续的手机震动声" |
| 对白 | 台词 / 旁白 | 文本 | 否 | "看不见我……你看不见我……" |
| 分镜提示词 | 用于生成分镜**图**的提示词 | 文本 | 是 | "[画面构图]：特写镜头，微俯拍…" |
| 视频运动提示词 | 用于生成**视频**的运镜 / 运动提示词 | 文本 | 是 | "[运镜]：缓慢推进…[动作]…" |

说明：

- **角色列组（角色N / 角色描述N / 角色图N）** 是一个可重复单元。单角色剧本只出现一组（截图1），多角色剧本横向扩展为多组（截图2 的角色1 / 角色2）。
- "分镜提示词"与"视频运动提示词"是衔接下游批量生成的关键字段，本期必须生成、可编辑。
- 字段是否必填用于：①生成时尽量补全；②校验提示。`必填=否` 的字段允许为空。

## 八、生成行为需求（产品视角 · 黑盒）

> 本节只规定"系统对用户表现出什么行为"，**不规定调用大模型的次数与编排方式**（单次/多次、是否流式、是否并行等属于实现，留给《技术改动文档》）。

**输入与输出**

1. **输入构成**：系统内置提示词（产品预置、不可见）+ 剧本原文（来自连入的文本节点）+ 用户的一句生成提示词。剧本可以很短，系统据此补全成"完整故事脚本"再拆镜。
2. **输出**：一张结构化分镜脚本表（§7），一行一镜、字段尽量补全，镜号从 1 连续递增。
3. **拆镜**：把故事拆为有序镜头序列，每镜补全 §7 字段。
4. **角色一致性**：同一角色在不同镜头中的"角色名 / 角色描述"保持一致；角色图本期可为占位 / 留空，由用户后续上传或在"角色生成"入口补充（路线图）。
5. **时长**：为每镜给出合理预估时长（秒），便于后续接入时间轴 / 视频合成。

**过程与状态**

6. **进度反馈**：生成是真实模型调用、需要时间，节点必须显示生成中状态（loading / 进度）。建议**逐行渐进呈现**——脚本表一镜一镜地出现，而非整段空白等待结束（提升体感速度）。
7. **空输入兜底**：无剧本（未连文本节点且节点内未粘贴）时，生成按钮置灰并提示"请先连入剧本或粘贴剧本文本"。
8. **失败处理**：生成失败时节点显示失败态，提供"重试"；不破坏已有内容。
9. **重新生成**：保留剧本与提示词重跑，覆盖当前脚本（覆盖前二次确认，见 R5）。

## 附：与现有画布概念的衔接（供评审参考）

- 脚本节点是**新的节点类型**，与现有「分镜组」（一组图像的规整宫格容器）是**两个不同概念**：分镜组管"图像的排布与交付"，脚本节点管"从文字到镜头的结构化编排"。两者可串联——脚本节点的下游批量出图，未来可回流进分镜组统一查看（路线图 P2）。
- 「文本」节点本期需从占位状态落地为可承载大段文本的真实节点，是本链路的输入起点。
