# 脚本节点 · 剧本生成分镜脚本 · 技术改动文档

> 配套文档：《脚本节点-剧本生成分镜脚本-功能需求文档.md》。
> 仓库现状：`CanvasFlow` 前端演示仓库，技术栈 **React 19 + @xyflow/react(React Flow) 12 + Zustand 5 + Tailwind 4 + TanStack Router/Start**。画布层（`routes/index.tsx`）、节点注册表（`nodeTypes`）、Zustand 单 store（`store/canvasStore.ts`）、节点卡片范式（`nodes/*.tsx`）、全屏编辑器范式（`composition/CompositionEditor.tsx` 经 `createPortal` 挂到 `document.body`）、右键菜单（`ContextMenu.tsx`）、节点底部浮层（`NodeToolbar`）均已存在，可直接复用。

### 1.3 脚本节点数据模型

脚本节点对外是一个可连线、可往后接的 `CanvasNode`；对内持有一张结构化分镜脚本表。新增 `data.script`：

```ts

export interface ScriptCharacter {
  id: string;
  name: string;   // 角色N
  desc: string;   // 角色描述N
  image?: string; // 角色图N（dataURL 或 URL）
}

/** 一行 = 一个镜头 */
export interface ScriptShot {
  id: string;
  index: number;             // 镜号（1-based，连续）
  duration: number;          // 时长（秒）
  description: string;       // 画面描述
  characters: ScriptCharacter[]; // 角色列组（0..N）
  refImage?: string;         // 参考（风格/构图参考图）
  shotType: string;          // 景别（特写/近景/中景/全景/远景…）

  emotion: string;           // 情绪

  sound: string;             // 音效

  imagePrompt: string;       // 分镜提示词（驱动下游出图）
  videoPrompt: string;       // 视频运动提示词（驱动下游生成视频）
}

export type ScriptStatus = "empty" | "generating" | "ready" | "failed";
export type ScriptView = "table" | "card"; // 脚本视图 / 创意视图

/** 可隐藏的列键；角色列组按"组"整体显隐 */
export type ScriptColumnKey =
  | "duration" | "description" | "characters" | "refImage" | "shotType"
  | "action" | "emotion" | "sceneTags" | "lighting" | "sound"
  | "dialogue" | "imagePrompt" | "videoPrompt";
// 注：「镜号」恒显示，不可隐藏。

export interface ScriptFilter {
  characterName?: string; // 只看含某角色的镜
  shotType?: string;      // 只看某景别
  keyword?: string;       // 画面描述/对白关键字
}

export interface ScriptData {
  title: string;            // 脚本标题（如"夏日初晴晚风"）
  promptText: string;       // 用户的一句生成提示词
  sourceText?: string;      // 生成时剧本原文的快照（来自连入的文本节点）
  model: string;            // 模型标识（如"GVLM 3.1"），仅展示用
  status: ScriptStatus;
  view: ScriptView;
  shots: ScriptShot[];
  hiddenColumns: ScriptColumnKey[]; // 字段可见性（被隐藏的列）
  filter: ScriptFilter;             // 画面筛选
  error?: string;                   // status==="failed" 时的错误信息
}

export interface CanvasNode {
  id: string;
  kind: NodeKind;
  x: number;
  y: number;
  data: {
    // ……既有字段保持不变
    text?: string;      // 新增：文本节点剧本原文
    script?: ScriptData; // 新增：脚本节点数据，仅 kind==="script" 时存在
```

## 2. 生成链路：前后端边界与注入点（核心）

> 这一节回答需求文档 §1.5 留下的"实现"问题：**后端在哪、调用怎么编排、如何流式**。原则是把"调用大模型"收敛到**一个文件、一个函数**（`services/scriptGen.ts`），store 与 UI 完全不感知"调了几次、用什么模型"。演示期给 mock，落地期把这个函数体换成真实后端请求即可。

### 2.1 契约（前端只认这个接口）

```ts
// services/scriptGen.ts —— 这是"实现"与"画布"之间唯一的边界

export interface GenerateScriptInput {
  sourceText: string;   // 剧本原文（来自文本节点）
  promptText: string;   // 用户那一句生成提示词
  model: string;        // 模型标识
}

/** 流式产出：每解析出一镜就回调一次，让脚本表"逐行冒出来"（感知速度） */
export interface GenerateScriptHandlers {
  onShot: (shot: ScriptShot) => void;   // 每得到完整一镜
  onDone: () => void;                    // 全部完成
  onError: (err: Error) => void;
  signal?: AbortSignal;                  // 支持取消（重新生成/关闭时）
}

export function generateStoryboardScript(
  input: GenerateScriptInput,
  handlers: GenerateScriptHandlers,
): void;
```

> 关键设计：**store 不关心后端调了一次还是多次**。"扩写→拆镜→逐镜补全"是 `generateStoryboardScript` 内部（或后端）的事；对画布而言，它只是一个"会陆续吐出 `ScriptShot` 的流"。这正是把"生成是黑盒"落到代码层的方式。

### 2.2 真实后端形态（落地时填进函数体，本仓库不实现）

后端代理一层，前端 `fetch` 一个 SSE / 流式接口：

```
POST /api/script/generate           （后端持有 API Key、系统内置提示词、计费扣点）
body: { sourceText, promptText, model }

后端内部编排（对前端不可见）：
  ① 系统内置提示词 + sourceText + promptText 拼成完整请求
  ② 调大模型，要求"结构化输出 JSON 数组，每元素一镜"（json_schema / function calling 锁结构）
  ③ 以流式（SSE）把每解析完整的一镜逐条下发

响应（SSE，每行一镜）：
  data: {"index":1,"duration":3,"description":"...","characters":[...],"shotType":"特写",...}
  data: {"index":2,...}
  ...
  event: done
```

- 前端拿到每条 `data` → 补 `id` → `handlers.onShot(shot)`。
- 速度策略（对应需求文档"逐行渐进呈现"）：**单次模型调用 + SSE 流式**即可"秒出第一行"；若后端为了质量拆成多段，也由后端内部并行 fan-out，对前端仍是一条流。详见配套图《script_to_storyboard_pipeline_slow_vs_fast》。

### 2.3 演示 mock（本仓库实现）

落地前，`generateStoryboardScript` 用定时器把 `data/scriptFixture.ts` 里的样例逐行吐出，复刻"流式逐行"观感：

```ts
export function generateStoryboardScript(input, { onShot, onDone, signal }) {
  const shots = pickFixture(input); // 取"最后的尊严"/"夏日初晴晚风"样例
  let i = 0;
  const timer = setInterval(() => {
    if (signal?.aborted) { clearInterval(timer); return; }
    if (i >= shots.length) { clearInterval(timer); onDone(); return; }
    onShot({ ...shots[i], id: `shot-${Date.now()}-${i}` });
    i++;
  }, 450); // 每 ~0.45s 冒一行，模拟流式
}
```

> 落地"接你自己的 API"时，**只改这一个函数体**：把 `setInterval` 换成 `fetch` + `ReadableStream`/EventSource 读 SSE，逐条 `onShot`。store、节点、全屏编辑器代码一律不动。

### 3.2 生成 / 重新生成

```ts
generateScript: (id) => {
  const node = get().nodes.find(n => n.id === id);
  const sb = node?.data.script; if (!sb) return;
  // 1) 取剧本：优先连入的文本节点；否则节点内 sourceText（兜底，默认取值④）
  const srcText = getConnectedScriptSource(get(), id) ?? sb.sourceText ?? "";
  if (!srcText.trim()) { /* UI 已置灰，这里二次保护 */ return; }

  get().pushHistory();
  patchScript(id, { status: "generating", shots: [], sourceText: srcText, error: undefined });

  const controller = new AbortController();
  scriptAbortMap.set(id, controller); // 模块级 Map，支持取消
  generateStoryboardScript(
    { sourceText: srcText, promptText: sb.promptText, model: sb.model },
    {
      onShot: (shot) => set((s) => patchShots(s, id, (arr) => [...arr, shot])), // 逐行追加 → 流式呈现
      onDone: () => patchScript(id, { status: "ready" }),
      onError: (err) => patchScript(id, { status: "failed", error: err.message }),
      signal: controller.signal,
    },
  );
},

regenerateScript: (id) => {
  // UI 层先弹二次确认（覆盖已有/手改内容），确认后：
  scriptAbortMap.get(id)?.abort();
  get().generateScript(id); // 复用，整体覆盖（默认取值②）
},
```

辅助：
- `getConnectedScriptSource(state, scriptId)`：在 `edges` 里找 `to===scriptId` 且 `from` 为 `text` 节点，取其 `data.text`（**单输入**，默认取值⑤；多条只取第一条并在 UI 提示）。
- `patchScript(id, partial)` / `patchShots(state, id, fn)`：仅改 `data.script` 的浅合并工具（仿既有 `patchTracks`，store 行 137）。

## 5. 状态流转（实现校验用）

```
AddNodePanel/右键 ──"文本"──► text 节点(粘贴剧本)
AddNodePanel/右键 ──"脚本→剧本生成分镜脚本"──► script 节点(status=empty)

text 节点 ──连线 out→in──► script 节点(获得 sourceText 来源)
script(empty) ──写提示词 + generateScript──► script(generating) ──onShot 逐行──► script(ready)
script(generating) ──onError──► script(failed) ──重试──► generating
script(ready) ──regenerateScript(二次确认)──► generating(整体覆盖)
script(ready) ──openScript──► 全屏编辑器 ──编辑(updateScriptShot/setScriptImage)──► 即时写回
script(ready) ──setScriptView──► 表格 ↔ 卡片
script(ready) ──toggleScriptColumn/setScriptFilter──► 仅改渲染，不动数据
script(ready) ──"生成分镜"(R11)──► 占位/下游节点(另立项)
```

每个箭头对应一个 action + 一条单测（§7）。

## 6. 边界与异常处理（对应需求 §8/§9，已按默认取值定稿）

| 编号 | 处理 |
|---|---|
| E-1 无剧本就点生成 | 生成按钮置灰 + 提示"请先连入剧本或粘贴剧本文本"（§3.2 二次保护） |
| E-2 多个文本节点连入 | 只取第一条作 sourceText，UI 提示"已使用第 1 段剧本"（默认取值⑤，单输入） |
| E-3 生成失败/超时 | `status=failed` + 错误信息 + "重试"，不破坏已有内容（§2.1 `onError`） |
| E-4 重新生成 | 二次确认 → abort 旧流 → 整体覆盖（默认取值②） |
| E-5 关闭/删除节点时仍在生成 | `abort()` 取消流，避免回调写已删除节点（§3.2 `scriptAbortMap`） |
| E-6 单/多角色 | 角色列组数 = 各镜 `characters.length` 最大值，动态展开（§1.5） |
| E-7 隐藏列/筛选 | 仅影响渲染，数据保留；「镜号」不可隐藏（§3.4） |
| E-8 图片跨域/读取失败 | 上传走本地 dataURL；mock 占位图与既有节点一致，失败降级占位 |
| E-9 删除脚本节点 | 复用 `removeNode`（联动删连线）+ 二次确认 |
