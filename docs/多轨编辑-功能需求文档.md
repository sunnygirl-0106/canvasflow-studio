# 视频合成 · 多轨编辑功能需求文档

> 状态：待评审（功能层）。本文只描述"做成什么样"，不涉及具体代码实现方案。评审通过后再出《技术改动文档》。
> 适用范围：CanvasFlow 演示仓库 · 全屏视频合成编辑页。
> 前置文档：《视频合成-功能需求文档.md》（单轨版本）。本文在其基础上增量。

---

## 一、背景与目标

当前编辑页只有**一条视频轨**：合成节点的数据是一个扁平的 `shots: Shot[]` 数组（见 `canvasStore.ts`），`TrackTimeline.tsx` 把它渲染成单条轨道，片段首尾相接、只能在这一条轨内拖动排序。音频在数据模型里**完全不存在**。

这次要把编辑器从"单视频轨"升级为"多轨"，对齐截图的目标形态：

- **视频**：最多 **2 条**轨道。第二条是**叠加 / 画中画轨**——当两轨在同一时间重叠时，V2 的画面叠加渲染在 V1 之上（可用于画中画、贴纸、转场叠加）。视频片段可以在两条视频轨之间拖动。
- **音频**：**不限条数**。音频片段从**画布上的音频节点**拖入轨道，可在时间轴上**自由摆放**（任意起始位置、可跨轨拖动、可与其它音频轨重叠播放）。这是当前 demo 完全没有的能力。

**范围声明（重要）**：本项目是前端 demo，目标是"前端能演示出多轨编辑与播放"即可。预览区的叠加合成与多音频混音做到**前端可视化/可感知**的程度即可，**不涉及真实的视频编码、音频解码与导出渲染**。导出仍沿用现有占位行为。

## 三、详细需求

### R1 · 数据模型升级（从单轨到多轨）

当前结构（单轨）：

```ts
// 合成节点 data
{ shots: Shot[] }   // 一条视频轨，片段首尾相接
```

目标结构（多轨）。建议引入"轨道 Track"层，统一承载视频片段与音频片段：

```ts
type TrackKind = "video" | "audio";

interface Track {
  id: string;
  kind: TrackKind;
  name: string;        // "V1" / "V2" / "A1" / "A2" …
  muted: boolean;
  clips: Clip[];
}

interface Clip {
  id: string;
  name: string;
  startSec: number;    // 【新增】片段在整条时间轴上的起始时间（秒）
  duration: number;    // 时长（受变速影响，沿用现有语义）
  baseDuration: number;
  speed: number;
  sourceIn: number;
  sourceOut: number;
  bindings: string[];  // 关联的画布节点 id
  thumbnail?: string;  // 视频缩略图 / 音频波形图
  color: Shot["color"];
  status: ShotStatus;
  // 音频特有（可选）
  kind?: "video" | "audio";
  volume?: number;     // 0–1，音频音量
  waveform?: string;   // 波形预览（demo 可用静态/伪波形）
}

// 合成节点 data
{ tracks: Track[] }
```

要点与待确认：

- **新增 `startSec`**：这是多轨的核心。当前单轨靠"前面片段累加"算位置（`layoutShots` 里的 `cursor`），多轨下不同轨各自独立，必须显式记录每个片段的起始时间。
- **视频轨的排布规则**：
  - **V1（主轨）**：建议保持"首尾相接、无空隙"的顺排逻辑（拖动=改顺序），与现状体验一致；`startSec` 由顺序自动推导。
  - **V2（叠加轨）**：建议允许**自由摆放**（有 `startSec`、可有空隙），这样才能把叠加片段对齐到 V1 的某个时间点。*待确认：V2 是否也保持顺排？建议自由摆放。*
- **向后兼容**：现有 mock 数据 / 已存合成节点用的是 `shots`。建议在读取时做一次迁移——把 `shots` 当作 V1 的 `clips`（并按累加补出 `startSec`）。*待确认：是否需要保留 `shots` 字段做兼容读取，还是一次性迁移 mock 数据即可。*
- **约束写进数据层**：`kind === "video"` 的轨最多 2 条；`kind === "audio"` 的轨不限数量。

> 备注：以上字段为建议，命名可在技术评审时再定。本节目的是说明"单轨 → 多轨"必须补的关键信息（轨道层 + 片段起始时间）。

### R2 · 时间轴多轨布局（对应截图）

把现在的"单条轨道"改为"多轨道区"，整体自上而下：

1. **时间刻度尺（Ruler）**：所有轨共用一把刻度尺与一根贯穿到底的播放头（沿用现有 ruler/playhead 逻辑，但播放头高度要覆盖全部轨道）。
2. **视频轨区**：V1 在上，V2（若存在）在其下。
3. **音频轨区**：A1、A2 … 依次往下排列，数量可增长。
4. 轨道区整体**纵向可滚动**（音频轨多了之后），刻度尺与播放头**横向滚动联动**（保持现有横向滚动行为）。

每条轨道是一行（沿用现有 `TRACK_H` 等尺寸 token，可按视频/音频区分高度）。左侧有轨道头（见 R8）。

*待确认：视频轨区与音频轨区之间是否需要一条分隔线 / 分组标题（"视频" / "音频"）。建议加，便于区分。*

---

### R3 · 视频双轨（最多 2 条，V2 为叠加/画中画轨）

- 视频轨**最多 2 条**：V1（主轨）+ V2（叠加轨）。
- 默认只有 V1。出现第二条视频轨的方式（二选一，*待确认*）：
  - **A. 拖出来自动建轨**：把片段从 V1 往上/往下拖到空白处，自动创建 V2 并落入；
  - **B. 显式按钮**："+ 视频轨"按钮，最多点一次（已有 2 条时置灰）。
  - 建议 A+B 都支持，A 更贴近截图直觉。
- **叠加合成关系**：同一时间 V1、V2 都有画面时，**V2 叠加在 V1 之上**。demo 阶段的预览表现见 R9。
- 已有 2 条视频轨时，任何"新增视频轨"的入口应**禁用并给出提示**（如"视频轨最多 2 条"）。

---

### R4 · 视频片段在双轨之间拖动

- 视频片段可以：
  - 在**同一轨内**水平拖动（V1 内沿用现有"拖动改顺序"；V2 内为改 `startSec`）。
  - **跨轨拖动**：从 V1 拖到 V2，或反向。
- 拖动时显示**落点指示**（沿用现有 `dropIndicator` 思路，但要支持纵向命中不同轨）。
- 跨轨约束：视频片段只能落到**视频轨**上，不能落进音频轨（拖到音频区应被拒绝/回弹）。
- 若拖动会导致视频轨超过 2 条（例如往视频区外的空白拖想再建第三条），**禁止**并回弹。

---

### R5 · 音频拖入（从画布音频节点）

这是 demo 当前完全缺失、本期要新增的核心能力。

- 音频片段来源 = **画布上的"音频"节点**（见 R10）。
- 交互：把画布上的音频节点**拖入**编辑页的音频轨区，即在该轨生成一个音频片段。
  - *待确认落地方式（二选一）*：
    - **方式一（连线/合成）**：与现有视频一致——音频节点连线汇入"视频合成"节点后，自动作为一个音频片段出现在音频轨（类比 `addToComposition` / `mergeToComposition`）。
    - **方式二（编辑页内拖拽）**：在编辑页内提供一个"素材区/音频节点列表"，直接拖到轨道上。
  - 建议优先**方式一**（与现有视频汇入逻辑同构，改动小、心智一致），方式二作为后续增强。
- 落入后音频片段显示：名称（如 `音频节点 3`）、时长、**波形**（demo 可用伪波形/静态波形图）。
- 音频片段落点的起始时间 = 鼠标释放处对应的时间（`startSec`）。

---

### R6 · 音频多轨

- 音频轨**不限条数**。
- 提供 **"+ 添加音频轨"** 入口（位置建议在音频轨区底部或轨道头区域）。点击新增一条空音频轨（A1、A2、A3…顺序命名）。
- 空音频轨显示占位提示（如"把音频拖到这里"）。
- 支持**删除音频轨**（轨道头上的删除；删除时若轨内有片段需二次确认，*待确认*）。
- 截图示例中有 4+ 条音频轨同时存在并各自有片段，需保证多轨纵向滚动与渲染性能在 demo 规模下流畅。

---

### R7 · 音频片段自由摆放

音频片段与视频片段的关键区别——**自由摆放**：

- **水平拖动**：可放到时间轴任意起始位置（改 `startSec`），**允许片段之间留空隙**。
- **跨轨拖动**：可从 A1 拖到 A2 等任意音频轨。
- **重叠播放**：不同音频轨在同一时间可以**同时有片段**（混音叠加），这正是多音频轨的意义；同一条轨内是否允许两个片段时间重叠，*待确认*（建议同轨内不允许重叠、自动吸附避让；跨轨允许重叠）。
- 音频片段同样支持**左右裁剪**与**改时长**（沿用现有 resize 思路，作用于 `sourceIn/out` 与 `duration`）。
- 选中音频片段后，属性区可调**音量 `volume`**（*待确认是否本期做*；建议至少保留静音/轨级音量）。

---

### R8 · 轨道侧边栏 / 轨道头

把现有左侧那一个全局静音按钮（`SIDEBAR_W` 那一列）扩展为**每条轨道一行的轨道头**：

- 每条轨道头显示：
  - **轨名**：`V1` / `V2` / `A1` / `A2` …
  - **静音切换**（沿用现有 `Volume2 / VolumeX`，但作用域从"全局"变为"该轨"）。
  - （音频轨）**删除轨**按钮。
- 区域底部 / 顶部放置：
  - **"+ 视频轨"**（已有 2 条时禁用）。
  - **"+ 音频轨"**。
- *待确认*：是否保留一个"全局静音"。建议轨级静音为主，全局静音可选保留在播放控制区。

---

### R9 · 预览合成（前端 demo 级别）

明确 demo 的预览表现，不追求真实渲染：

- **画面（视频双轨叠加）**：
  - 预览区先取 **V1** 在当前播放头时间的画面作为底图（沿用 `PreviewStage` 的"找当前 shot"逻辑，但改为按 `startSec + duration` 命中）。
  - 若 **V2** 在该时间也有片段，则把 V2 画面**叠加渲染在 V1 之上**。demo 表现建议：V2 以**画中画小窗**（例如右上角缩略框）或半透明叠层方式呈现，足以让人看出"两轨在叠加"即可。*待确认 V2 的默认呈现样式（画中画窗 / 全屏叠层 / 可后续做位置缩放）。*
  - 若该时间只有一轨有画面，就只显示那一轨。
- **声音（多音频轨混音）**：
  - demo 不做真实混音解码。表现层面：
    - 时间轴上音频片段照常显示、随播放头推进高亮；
    - 轨级/片段级**静音、音量**状态在 UI 上生效并可见；
    - *待确认*：是否需要真的用 `<audio>`/WebAudio 同时播放多条音频（前端其实可做到简单多路播放）。建议 demo 至少支持"主音轨真实出声 + 其它轨可视化"，能力够则全部出声。
- 全屏播放视图（现有 `FullscreenPlayer`）同步适配上面的画面叠加逻辑。

---

### R10 · 画布侧：新增"音频"节点

为支撑 R5，画布上需要有"音频"素材节点：

- 在"添加节点"面板新增 **"音频"** 项（图标建议用音符/波形类，如 `lucide` 的 `Music` / `AudioLines`）。
- 音频节点形态：紧凑卡片，显示名称 + 波形/时长（demo 用占位音频与伪波形）。
- 连接规则：音频节点从**右侧**输出，连入"视频合成"节点（沿用现有左右连线规则）。汇入后按 R5 方式一生成音频片段。
- *待确认*：音频节点是否需要"AI 生成音频/配乐"之类的子类型，还是先只做"本地/占位音频"一种。建议先一种。

---

### R11 · 交互与边界规则

- **吸附**：拖动片段时对齐到刻度（秒/帧）、对齐到播放头、对齐到相邻片段边缘（沿用现有 `Math.round(t*10)/10` 量化思路）。
- **同轨重叠**：视频 V1 顺排不重叠；V2 与音频轨"同轨是否允许重叠"按 R3/R7 的待确认结论执行（建议同轨不重叠、跨轨允许）。
- **空轨**：空的视频/音频轨显示占位提示；空音频轨可被删除。
- **约束提示**：触发"视频轨已达 2 条""不能把视频拖进音频轨"等约束时，给轻量 toast/回弹反馈（可复用 `CompositionCoachToast`）。
- **撤销/重做**：所有新增操作（建轨、删轨、跨轨拖动、音频拖入、改 `startSec`）都要纳入现有 `pushHistory` 历史栈。
- **选中态**：选中片段/轨道的高亮沿用现有 `selectedClipId` 机制；多轨下需保证选中跨轨唯一。

---

### R12 · 非目标（本期不做）

- ❌ 真实视频编码 / 音频解码 / 服务端渲染导出（导出沿用现有占位）。
- ❌ 视频轨超过 2 条。
- ❌ V2 画中画的精细位置/缩放/关键帧动画（demo 先固定样式，后续再说）。
- ❌ 音频高级处理：淡入淡出、变调、降噪、EQ 等。
- ❌ 转场特效库、字幕轨、贴纸轨等其它轨道类型（本期只做 视频×2 + 音频×N）。
